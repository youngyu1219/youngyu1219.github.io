Miniconda 多环境 + GDAL 安装踩坑笔记

踩坑记录 2026-10-25 约 6 分钟阅读

做 GIS 和遥感，最烦的不是写代码，而是环境。不同项目依赖的 GDAL、Fiona、rasterio 版本经常打架。这篇记录我用 Miniconda 做环境隔离，以及安装 GDAL 时踩过的坑。

一、为什么要用 conda

pip 装地理空间库常常卡在「找不到 GEOS / PROJ」这类编译问题上。conda 直接给预编译好的二进制包，省心很多。所以我的原则是：地理空间相关的库，一律优先走 conda-forge。

先建一个独立环境，别污染 base：

# 创建名为 gis 的环境，指定 Python 版本
conda create -n gis python=3.11 -y

# 激活
conda activate gis

二、安装 GDAL 的坑

最常见的错误是「pip 装完 import 报错」。原因是 pip 版 GDAL 需要本机已有对应版本的原生库，很容易版本对不上。改用 conda-forge 安装：

# 从 conda-forge 装，版本会自动匹配
conda install -c conda-forge gdal fiona rasterio -y

几个常见报错与处理：

报错现象大概率原因处理
ImportError: DLL load failed原生库版本不匹配统一用 conda-forge 安装
找不到 PROJ 数据库PROJ_LIB 环境变量缺失重装 proj，检查环境变量
pip 与 conda 混用后冲突同一库装了两份新建环境重来更省事

经验之谈：环境一旦被 pip 和 conda 混着装乱，最快的方法不是修，而是 conda env remove 掉重建。

三、注册 Jupyter 内核

环境建好了，但 Jupyter 里看不到它。需要手动把环境注册成一个内核：

# 在 gis 环境里执行
conda activate gis
pip install ipykernel

python -m ipykernel install --user --name gis --display-name "Python (gis)"

之后打开 Jupyter，内核列表里就能选到 Python (gis) 了。如果启动内核报错，多半是 ipykernel 没装到对应环境里。

四、一点小结

  • 一个项目一个环境，命名清楚，别嫌麻烦。
  • 地理空间库优先 conda-forge，少碰 pip。
  • 环境乱了就重建，比修补省时间。
  • 把常用命令记下来，下次直接抄。
