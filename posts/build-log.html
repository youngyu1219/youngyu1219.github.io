从一张白纸到国风博客：我为什么重新搭站

建站手记 2026-10-28 约 8 分钟阅读

原来的主页是一页式的「自我介绍」：一张封面、几个板块、一段联系信息。它能用，但装不下东西——笔记、项目、踩坑记录全散落在各种地方。于是我决定把它推倒重来，做成一个真正的个人博客。

为什么要重做

说到底，是「沉淀」两个字。学 GIS 和写代码一样，不写下来就很快忘。博客逼我把一件事讲清楚：从「我做过」变成「我能说明白」。这本身也是对自己的一种训练。

其次，我想让站点看起来「像我」。模板站千篇一律，不如自己动手，从配色到排版都按自己的审美来——于是有了现在这套国风国潮的路子。

技术选型：为什么不用现成框架

Hexo、Hugo 都很好，几分钟就能跑起来。但我这次想要的是完全掌控视觉：每一个留白、每一条金线、每一个印章的位置，我都想自己决定。

  • HTML5 —— 负责语义化的结构，一页一页手写。
  • CSS3 —— 用变量统一配色与字体，Grid / Flex 排版。
  • 原生 JavaScript —— 滚动揭示、轮播，不引入任何库。
  • 纯静态 —— 没有后端、没有数据库，部署极简。

选型没有对错，只有合不合适。我要的是「轻」和「可控」，所以选择了最朴素的三件套。

目录结构

整个站点就是一堆文件，结构一眼能看懂：

blog-tang/
├── index.html        # 首页
├── about.html        # 关于我
├── projects.html     # 项目
├── archives.html     # 文章 / 归档
├── tech.html         # 技术说明
├── 404.html          # 404 页
├── css/style.css     # 设计系统
├── js/main.js        # 交互脚本
├── img/              # 配图
└── posts/            # 每一篇文章

部署：越简单越好

静态站点最大的好处，就是部署几乎不花力气。把整个文件夹传到 GitHub Pages，或者任意一台装了 Nginx 的服务器，就能访问。本地预览更简单：

# 直接双击 index.html 就能看
# 或者起一个本地静态服务，避免路径问题
python -m http.server 8080

# 然后浏览器打开 http://localhost:8080

踩过的坑

  • 路径问题：文章放在 posts/ 子目录里，引用样式和图片必须加 ../，一开始漏了，页面直接「裸奔」。
  • 移动端菜单：抽屉菜单打开后要能点击空白处关闭，否则在小屏上很难受。
  • 动效过度：第一版加了太多动画，反而晃眼。后来只保留滚动揭示和轮播，克制一点更耐看。
  • 图片体积：大图会让首屏变慢，后面要统一压一压。

接下来

先把内容补齐：环境配置、遥感反演、数据库建库，一篇篇写。视觉上还会继续调，但方向是「更干净」，不是「更花哨」。

如果你也在搭自己的站点，欢迎交流——踩过的坑，能少一个是一个。
